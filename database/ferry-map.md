# フェリー地図master

`ferry-map.json`は地図画像上の表示用masterです。SQLの航路・運賃masterとは別に管理します。
`FerryMapMaster`が読込時に座標範囲、地域参照、都道府県・正規名・alias・優先順位の重複を検証します。

- `regions`: UIの地域ID、都道府県名、未登録港の配置先`center`。
- `ports`: 港の正規名`name`、所属`region`、照合用`aliases`、`priority`、`position`。
- 座標は地図画像の左上を原点とする0〜100の百分率です。緯度・経度ではありません。
- aliasは既存仕様どおり大文字小文字・空白を変換せず部分一致します。小さい`priority`が優先です。
  `苫小牧東`は`苫小牧`より、`大阪港国際`は`大阪港`より先に照合します。
  JSON内の行を並べ替えても優先順位は変わりません。

## 分類・fallback契約

1. 航路の都道府県名を完全一致で地域へ変換します。空欄・未知表記・末尾空白・外国名は
   `overseas`に分類し、必ずその中央座標を使います。既知の港名でも例外にしません。
2. 国内地域の場合、港名に一致するaliasがあれば港の座標を使い、なければ地域中央へ配置します。
3. 表示名・選択IDとして使われる`departure.name`／`arrival.name`はDBの原文を維持します。
   masterの正規名への置換は行いません。
4. masterの港所属地域と航路の都道府県が矛盾していても、従来どおり分類は航路側、座標は
   港側を使います。所属地域はmaster上で検証できる情報として保持します。
   この矛盾を自動修正するとUIの地域選択が変わるため、航路データを確認して別途修正します。

`overseas`は「外国であることを確認済み」の意味ではなく、国内都道府県に一致しなかった分類です。

## 更新手順

港追加・表記変更時は正規名、所属地域、alias、画像上の座標を確認し、重なるaliasの
優先順位を明示してください。新しい表記と未登録時の挙動をテストへ追加します。
`php tests/run.php`でmaster検証と分離前の港projection契約を確認します。
既存fixtureは`tests/fixtures/ferry-map-ports.json`です。意図的に挙動を変える場合だけ差分を確認して更新します。

`FerryMapService`は航路の表示データにmasterの港projectionを組み合わせます。
JavaScriptは地域・出発港・到着港の選択、向き反転、線・pin・結果カードの描画を担当します。
JSON endpointのkey構造を変える場合は両者を同時に確認してください。
